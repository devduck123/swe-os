# Changelog

Projects pin a version in their `AGENTS.md`. Check here before moving to a new one. Versions follow [semver](https://semver.org): a minor version can change skill steps or rules, and a major version means a project's `AGENTS.md` may need edits.

## Unreleased

- **Several agents, reviewed.** The stop no longer claims two agents do a day's work in an hour. It says your review is the bottleneck, to remove a worktree when its PR merges, and that a changelog or tracker conflicts even when the features don't. Routine permission prompts can go to allow rules or an auto-approve mode, and the How I do it line is Tommy's.
- **Desktop apps, reviewed.** Shipping a desktop app no longer states Apple's current signing rules or App Store terms. It says unsigned apps look like malware on macOS and Windows, to look up each platform's rules well before launch, and that a store trades control for less work. A new miss, from building a Mac utility: macOS ties each permission to the app's signature, so a build signed differently each time loses its grants on every rebuild. Its How I do it line is where Tommy actually is, since he hasn't shipped one yet.
- **Keeping a codebase healthy, reviewed.** The stop no longer says agents never clean up on their own or can't see last week's helper: they don't look unless told. Stale docs get believed over the code, with a real case where wrong docs made every install reset a permission. Cleanup starts when it hurts, a slow change or the same bug fixed twice, which is what Tommy does.

## v0.9.0 (2026-11-19)

Agents now look up what moves fast instead of trusting these pages, and treat my profile as where they start, not a limit. Pages that disagreed now agree, provider details that go stale are gone, and a typical feature loads fewer concern pages. Eval runs no longer get your logins. Evals haven't measured any of it yet.

- **Agents look up what moves fast.** A new rule for every task: when an answer depends on a version, an API, a framework default, a price, or a provider's rule, check the project's installed version and its current docs, and say when an answer is from memory. Stops teach the idea and name a product only as an example.
- **The profile is taste, not a limit.** Rule 1 now says the profile is where an agent starts: when it would do something differently and better, it proposes that and says what it buys. This used to apply only to the default stack. The accessibility and motion floors in design taste aren't taste, and still hold.
- **Two stops reviewed.** Going public drops the email-sending bullet, adds favicons and icons, and says what Tommy actually does: Vercel and its analytics for a small project. Caching no longer prescribes a Next.js API or claims what its defaults are. Email-sending rules leave Launch too, for the agent to look up.
- **One quick retry while someone waits.** Two stops said never retry while a person watches a spinner, and the Reliability concern said retry a few times. Now all three say one quick retry of a temporary failure, then tell them, with longer loops kept for background work.
- **Pages that disagreed now agree.** The project template merges once checks pass and someone has seen the change work, like rule 14. Voice's "Keep momentum" matches rule 4: assume, say it, keep going, and stop only before what's hard to undo. Start-project uses the profile's host instead of naming Vercel, checks the secret scanner on a scratch folder instead of committing a fake key, and says why a new repo's first commit goes straight to `main`. Design taste's floors are only the accessibility and motion rules; one design system per project gets its own section. Favicons go where the framework looks for them. Adopters copy `tommy.md` too, so their agent doesn't think they're Tommy.
- **Fewer facts that go stale.** Security, Launch, AI features, start-project, the side-project stack, and the default stack no longer state a provider's current plan limits, key names, or file names. They name the trap and send the agent to the current terms. Account MFA moves from the Security concern, which loads on most features, to start-project's list for the user.
- **Five claims fixed.** Two branches that both add migration 7 need the second renumbered, since rebasing alone doesn't fix it. macOS permissions come from system prompts, and some only from System Settings. A few thousand rows can still be read in full even with an index, so seed tens of thousands. The METR slowdown study is dated 2025. Trust boundaries says "the public key" instead of Supabase's anon key, which is being replaced.
- **Fewer concern pages per feature.** The routing table sends uploads, sign-in, model calls, new packages, outside services, stored data, and caching to fewer pages, where one page already covers the risk. Concern pages drop their "Triggered by" lines, which had drifted from the table, and lines that repeated the rules or build-feature. A signed-in form that stores data now loads about 2,950 words of concerns instead of 3,400.
- **Stops that repeated each other link instead.** Shipping changes you can undo, and Performance and cost, point to the stops that own migrations, indexes, and caching instead of retelling them.
- **The site follows its own Launch page.** A `robots.txt` points at the sitemap, every page names the site and describes its social card, the card no longer cuts a sentence off, and production builds count visits with Vercel Web Analytics, which sets no cookies.
- **Eval runs don't get your logins.** Each run used to inherit your home folder and environment, so an agent could reach whatever `gh`, `vercel`, `supabase`, or `npm` account you were signed into. Now every run gets an empty home folder and a short list of environment variables, and logs in with `CLAUDE_CODE_OAUTH_TOKEN`. The [evals README](evals/README.md#run-a-round) says what that doesn't stop, like the network. The learner test no longer reads this repo's `CLAUDE.md`. The validator now checks each stop's number and stage against the track page, which caught the closing recipe filed as Design. CI runs once per PR commit instead of twice, the private-terms check covers file names and commit messages, and Astro 7.4.13 clears three high-severity advisories.

SWE OS covers more of the road from idea to real users: launching in public, payments, desktop apps, caching, running several agents at once, and keeping a codebase healthy. Pages and a refactor skill fill the gaps that three reviews and a coverage audit found. It also talks about "the user" instead of me, and spells out how to adopt it in a new or existing repo. None of the new pages has been measured by evals yet.

- **Four new stops, a desktop concern, and a refactor skill.** The track is 27 stops: Caching without stale data (Design), Running several agents at once (Build: worktrees, ports, migration numbers, session cost, permission rules), Shipping a desktop app (Ship: signing, notarization, auto-update, old versions), and Keeping an agent-built codebase healthy (Improve). A Desktop apps concern covers installed apps. The new refactor skill changes code's shape with today's behavior pinned by tests first. Verifying now means testing what you started from your own checkout, since a running server may be another session's.
- **A voice for each product, and smaller gaps.** `docs/brand.md` now starts with how the product sounds, kept even when there's no art, and product copy follows it. Security asks for recovery codes you can reach without your phone, the strongest protection on the email and domain that reset everything else, and a real Content-Security-Policy. Product and UX asks for a support channel you actually read. Data covers reviewed scripts for hand fixes and backing up uploaded files, Security covers throwaway signups and spam through what users can publish, Reliability catches reminders that drift with the clocks, and Privacy says to tell the people a leak affected.
- **Payments, upgrades, and account flows.** A new Payments concern: access comes from the provider's webhook, never the success page, and cancels, failed renewals, refunds, and disputes take it away. Upgrading a dependency or framework now triggers the dependencies concern, and start-project asks you to turn on Dependabot security updates. Security covers what happens past sign-in: verified emails before linking accounts, single-use reset links, and ending other sessions.
- **A lighter self-critique.** build-feature runs review-change on its own diff only for UI and for changes that touch a floor, like auth, payments, or personal data. Everything else gets one hard read.
- **Going public.** A new concern, Launch, and a new Ship stop, Going public, cover what the track skipped: link previews and their caches, one canonical domain, launch email that lands in the inbox, a privacy page before the first signup, bots on public forms, analytics before the spike, and free plans that forbid commercial use. The track is 23 stops now.
- **Skills talk about "the user", not me.** Someone else adopting SWE OS had their agent report "For Tommy to do". The profile still says whose preferences they are, and a project's own profile can replace any of its files, falling back to mine for the rest.
- **Adopting it is spelled out.** The README has a section for a new project and for an existing repo. An existing `CLAUDE.md` gets `@AGENTS.md` added, since without it Claude Code never reads SWE OS. The template's two `<path>` placeholders have distinct names, its clone path matches the README, and it says how to follow links when reading at a tag.

## v0.7.0 (2026-11-14)

Agents see their PRs through to merged. A merge waits for green checks on the latest commit, a branch up to date with `main`, and the change seen working, then goes ahead on my approval or where a project hands merging over. Projects also read SWE OS at their pinned tag without touching the clone's checkout.

- **Agents ask for merge autonomy instead of assuming it.** Where a project's `AGENTS.md` doesn't say whether agents merge their own PRs, an agent asks once, and start-project asks during setup. A yes goes into `AGENTS.md`.
- **Agents see a PR through to merged.** A merge waits for a gate: required checks green on the latest commit, the branch up to date with `main`, and the change seen working. Then it goes ahead on a clear approval, or on its own where a project's `AGENTS.md` says agents merge their own PRs. In one session I had to say "merge" about ten times, and an agent merged before checks finished. build-feature's self-critique now fixes real bugs and lists the rest as follow-ups, so review doesn't grow the change.
- **Projects read SWE OS at their pinned tag without checking it out.** The project template said to `git checkout` the pinned version in the local clone, which detaches the branch of anyone who also works on SWE OS there. It now reads files with `git show <tag>:<path>`.

## v0.6.0 (2026-11-14)

Lessons from building a real product page with SWE OS. Design starts from what the product is, agents critique their own work before showing it, product copy reads like a person wrote it, and setup avoids the traps a real repo hit. With SWE OS, design evals score 3.0 vs 1.0 on a plant app and 2.67 vs 1.67 on a Mac utility's coming-soon page.

- **Fairer design evals.** Graders now give a reason for every Design score, and the rubric checks that a design fits how serious the product should feel, so a cartoon on a serious tool scores low however well it's drawn. The dark-mode check now sees backgrounds set on `<html>` or as gradients. Each run records the commands the harness blocked, and graders don't count a blocked check against the agent. Harmless helpers like `cd`, `head`, and `sleep` aren't blocked anymore: they used to stop runs without SWE OS from looking at their own page. A private round now refuses a temp folder, which is how one round's results were lost. A round, or its grading, now stops when Claude Code reports a session limit, instead of counting cut-off runs and grades. A new scenario asks for a coming-soon page for a Mac utility whose name invites a mascot.
- **Design taste pushes past the first idea.** Agents say what the obvious version would be and build something else. On a new product or a redesign, they write three short directions without asking, and ask once before building more than one, since that costs real tokens. New sections say to hire a designer for a real project, use code as your artist if you can't, and ask for art that feels drawn by a person: a hand or a real craft behind it, real range, art with a job, a bold layout. The "look at what others do" step is gone, because no agent followed it. The five-second motion rule now covers anything that moves on its own, not only loops.
- **A design eval.** A new scenario asks an agent to make a plain app feel like a product. The harness screenshots each result in both themes and measures the rules (accessibility, sideways scrolling, motion, touch targets), so graders judge the page and not only the diff. First result: Design 2.67 with SWE OS vs 1.33 without, at about 2× the cost, with gaps listed in the [evals README](evals/README.md#results-so-far).
- **Product pages lead with real use.** build-feature now says to lead with what people would use a product for most, because five of six sites in a private round led with the first example in the product's docs. start-project recommends preview deploys on the host a project already uses, and Vercel only if it has none.
- **A favicon and a social card, every time.** Design taste now asks for both on every site, drawn from the product's own art, because a site an agent built for me shipped without a social image. The brand template lists them, and the design eval measures what a tab and a shared link would show.
- **Design starts from what the product is.** Before drawing, agents learn what the product does, who uses it, and where it lives, then pick how serious it should feel. A tool should look at home on its platform, with the charm in the details and one metaphor at most. If they can't tell, they ask one question first, because a wrong guess costs a rebuild. Pages show the real product working, and copy stays plain. The lines that pushed every product toward playful are gone, and Design taste is shorter than before, with my palette moved to [its own page](profile/palette.md).
- **Agents critique their own work before reporting.** build-feature now ends by running review-change on its own diff and, for UI, looking at the screenshots cold as a senior designer would. On a real site, that kind of review found the bugs the builder's checks missed and drove the best design fixes, but only when I asked for it.
- **Product copy reads like a person.** Writing now covers a product's own words: say what it does plainly, no slogans or three-beat taglines, the app's real strings, plain status, and a reread for any line that could sit on another product's page.
- **A website gets the skills too.** start-project for its repo and build-feature for each change, even on a casual ask, and both skill descriptions now say so. Agents read SWE OS files one at a time, so a truncated read can't slip by. A product demo shows what sets the product apart, not only the common case, and each project fact lives in one doc.
- **start-project avoids three setup traps.** It pushes `main` before any other branch, since the first branch pushed becomes the default and Vercel's production branch. It scans secrets on pull requests, since the gitleaks action fails on a push that includes the first commit. And a website goes on Vercel with the import steps in the report. `.env.example` appears only when there are variables, and the template asks for the real SWE OS clone path.
- **More from the same real use.** UI quality now checks layout shift and sweeps widths where text sits on art. Browser tests start their own server instead of reusing a stale one. debug rules out the environment with a known-good baseline. Sites follow the system theme with a toggle, and new tokens cover light and dark. After a rename or restyle, agents search for the old value, head tags included. A private preview comes before anything goes public, details of an unreleased private project stay out of public places, and once I've seen a change, any clear approval means merge. An agent sent to the SWE OS folder to build something else is told to work from that project's folder.

## v0.4.0 (2026-10-17)

How I work, written down: a branch per change, designs priced before building, design taste, and a track that separates my habits from the standard. Projects pinned to v0.3.0 should read the guidance changes before moving.

**Guidance changes**

- **A branch and a PR for every change.** New rule 14. start-project commits the setup as the first PR and lists a ruleset on `main` for Tommy to turn on.
- **System design with real costs.** shape-project now prices each part at the expected audience, 10 times it, and a bad month, with the math shown and dated sources, and the user agrees to the design before setup. It lands in a new `docs/design.md` template.
- **Docs that stay current.** The project template says where docs live (PROJECT.md, `docs/design.md`, `docs/decisions/`) and to update AGENTS.md when work adds a command or convention. It can name an area Tommy is learning, and build-feature leaves a `TODO(human)` there.
- **Design taste.** [profile/design.md](profile/design.md) replaces the UI taste paragraph. Agents pick each product's own visual direction and are pushed past default styling: micro-interactions, real art, motion with character. A few rules don't bend: contrast, reduced motion, motion that never blocks, accessible art, and one token system per project. Agents look at how similar products handle a screen first (Mobbin, live sites). Brand art is kept as components in `components/brand/`, with its style and an index in a new `docs/brand.md` template. My portfolio's palette is there as an option, with its contrast fixed.
- **A fresh session per feature.** In the project eval, one long session made later messages cost 5 to 10 times the early ones. The README and build-feature now say to start a fresh session for each feature, with PROJECT.md complete enough to pick up from.
- **Build what was asked.** If build-feature would design something differently, it says so in one line and builds what was asked. It doesn't re-ask a question that's been answered, and goes with its recommendation when an answer doesn't settle it.
- **Reviews fix what they're asked to fix.** When asked for fixes too, review-change fixes every blocking finding before reporting, and picks the safer default when a fix needs a product decision.
- **Setup a stranger can follow.** start-project requires a CI secret scan, makes the local pre-commit hook optional, and runs its fresh-clone check in a temporary folder outside the project.
- **learn corrects first.** A new eval walks through a PR and quizzes a simulated user who gets two things wrong. The first round tied, and one SWE OS run never corrected the user because it was busy writing LEARNING.md. The walkthrough is now one outcome, corrections first, and SWE OS scores 2.92 vs 2.53. LEARNING.md is gitignored in public repos unless you say otherwise.
- **Talk to Tommy, not about him.** Graders caught replies saying "Tommy's default" to Tommy. Voice now says "your defaults".
- **Guidance fills gaps, not defaults.** skills/README.md and AGENTS.md now say SWE OS covers only what agents skip by default, plus my preferences. Where an agent's own defaults already do the job, it keeps them. "The standard" applies only when PROJECT.md says the project's maturity or exposure calls for it, and a rule stays only while evals show it helps.

**The track and the site**

- **My habits, apart from the standard.** Every track stop now ends with "How I do it" (what I do on my own side projects, labeled as mine), "The standard" (what teams add beyond that, each with the signal that it's time), and "Before you ship, check" (the floor, every time). "What I'd do" is gone. The sections are agent-drafted for now, and I'll rewrite them in my own words.
- **A sidebar split the same way.** Learn (the track, stages collapsed), How I build (my defaults, my design taste, and the recipes), Standards (the principles and one page per risk), Skills, and About me. The landing page's Concerns card is now Standards, and the How I build card links my defaults.

**Evals**

- **The project eval.** `node evals/project/run.mjs` builds a book club app over seven messages, with and without SWE OS, in a fresh session per message by default (`--sessions one` keeps one long session), then runs `npm install`, `npm test`, and `npm run build` on each final repo and reviews both blind. It's tested end to end with a stand-in `claude`. The scenario harness now shares its Claude helpers through `evals/harness/common.mjs`. With fresh sessions, SWE OS scored 2.63 vs 2.50 at 1.8× the cost.
- **A simulated user in the project eval.** When the agent ends a message with a question, a separate Claude playing the owner answers it from the facts, at most twice per turn, and never says "go ahead". `--fixed-answers` keeps the old fixed reply. The defaults are now a $120 budget and $12 per message, enough for all seven turns, and a review missing reasons gets one follow-up.
- **The skills keep their steps.** An ablation rewrote debug, review-change, and explain as outcomes only. All three scored lower than the current versions run the same day, so nothing was cut.

## v0.2.0 (2026-10-13)

From MVP to product. Projects that pin v0.1.0 should read the guidance changes below before moving.

- **Agents build first, then ask.** Rule 4 and build-feature's stop rule: when a question doesn't block code you could undo, make the likely assumption, say it, build, and ask at the end. A server route for a requested feature, or a substitute for a package that doesn't exist, counts as implied. Rule 6 asks only before signing up for or turning on a paid service the user hasn't asked for.
- **Shorter reports.** One line names the handled concerns; only open ones get their own line. Answers to questions skip the concern report (rule 9).
- **Expo.** The secrets guide and security concern cover `EXPO_PUBLIC_` and other values shipped inside a mobile app.
- **Evals you can run.** `node evals/harness/run.mjs` runs every scenario with and without SWE OS through Claude Code, grades blind, and writes a summary. Results from the first three rounds are in `evals/README.md`.
- **Claude Code plugin.** `/plugin marketplace add devduck123/swe-os`, then `/plugin install swe-os@swe-os`. The seven skills trigger on their own, and the plugin updates when a new version is released.
- **Pin a version.** The project template reads SWE OS at a tag, from a local copy or from the raw files on GitHub, and `start-project` fills in the latest tag.
- **Use your own profile.** A project's `AGENTS.md` can point at your own voice and default-stack files instead of Tommy's.
- **Feedback.** Issue templates for wrong facts and agent friction, an edit link on every page, and private vulnerability reporting. Rule 13 points agents at the feedback form.
