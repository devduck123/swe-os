# Project

## Now

**v0.3.0 released on 2026-10-17.** The site is live at https://tommy-swe-os.vercel.app, and the repo is public under MIT (code and templates) and CC BY 4.0 (writing). Maturity: prototype.

What's in it:

- The 22-stop track, tuned against a learner test: 91% of in-character readers take away the intended lesson. It goes past solo side projects into professional engineering. Tommy will revisit the level after a real-use baseline.
- Seven skills and 17 concerns, used from the site, a local clone, or the Claude Code plugin. Projects pin a version.
- Evals that meet the bar: SWE OS ties or wins every scenario, with no serious flaws of its own, and is much stronger at verifying its work. It costs about 2× the tokens. See [evals](evals/README.md#results-so-far).
- Guards on the public repo: secret scanning on every commit and PR, GitHub push protection, and a protected `main`.

## Next

1. **Tommy's design system.** `profile/design.md`: principles and default light and dark tokens, drafted from his portfolio and OpenPacks. `start-project` sets the theme up on day one, and features use only tokens. Needs Tommy's review.
2. **More `learn` evals.** The walkthrough eval exists: SWE OS now scores 2.92 vs 2.53 (3 reps). Catch-up and own-a-piece are still untested.
3. **Trim the agent guidance to what earns its place.** Audit the skills and concerns for step-by-step procedure the model already handles, and rewrite it as outcomes and limits. Then run ablation evals (the suite with one rule or section removed) and delete what doesn't move the score.
4. **A real-use baseline with Tommy.** The project eval gave the synthetic one: with a fresh session per feature, SWE OS scored 2.63 vs 2.50 at 1.8× the cost (see [project eval](evals/project/README.md)). Next, Tommy builds one real side project with it, with a learning area named in its AGENTS.md, and records what helped and what got in the way.
5. **The track's level, in Tommy's words.** Tommy rewrites "How I do it" in his own voice and decides what a solo builder needs first and what's professional depth.
6. **Real readers.** Share the site with a few people who build with AI, and turn on Vercel Web Analytics.
7. **On each new model:** rerun the evals, and delete guidance that no longer helps.
8. Try one task in Codex with each path.
9. A custom domain, when wanted. Change the URL in `astro.config.mjs`, the README, and the repo's homepage.

| No installer. Agents read the repo or site.                                                                                                                                                                                     | Nothing to sync or version per project. A project's AGENTS.md records which version it follows.                                                                                                                                                                          | Reading over the network proves too slow or flaky.                                                         |
| Built for anyone, primarily Tommy                                                                                                                                                                                               | Tommy is the main user, but the site and repo are public, so others need to use it without forking or hitting dead ends.                                                                                                                                                 | Other people start contributing regularly.                                                                 |
| An optional Claude Code plugin as a third path; reading the site or a clone stays the default                                                                                                                                   | Installed skills trigger on their own, without pasting a prompt every task. Keeping it optional keeps "no installer" true.                                                                                                                                               | The plugin format keeps changing, or nobody uses it.                                                       |
| Agent guidance covers only what models don't do well by default, plus Tommy's preferences; outcomes and limits over procedure; every rule has to earn its place in evals, rechecked on each new model                           | Every time SWE OS hurt in evals, it was fighting the model: stop-and-ask rules, a five-section report, a required secret hook. It helped most where defaults are weak: verification +1.07, setup +0.83, debugging +0.58. Models keep improving, so SWE OS should shrink. | A new model makes most rules redundant, or ablations show a rule is load-bearing in ways we didn't expect. |
| Evals run headless on Tommy's Max plan, capped at $50 API-equivalent per round                                                                                                                                                  | Headless runs worked in the agent-path test. The cap keeps a round from eating the plan's limits.                                                                                                                                                                        | The first round shows the cap is too low to answer anything.                                               |
| The eval bar is per scenario: B ties or beats A within noise everywhere, has no serious flaws of its own, ties the two-line fix on cost, and clearly wins where SWE OS teaches                                                  | Rounds 4 and 6 plateaued at +0.29 and +0.30. On tasks Opus already does well (2.3–2.7 of 3 without SWE OS) there's little room, so an average target rewards the wrong thing.                                                                                            | The model gets much weaker or stronger, or new scenarios target new skills.                                |
| Agents build what the request implies and ask at the end, instead of stopping to ask first                                                                                                                                      | Eval rounds 1 and 2: with SWE OS, agents asked for a plan sign-off on features the user had already asked for, and scored lower than without it.                                                                                                                         | Agents start building things users didn't want.                                                            |
| Two agent paths: raw Markdown from the site with curl, or a local clone                                                                                                                                                         | Claude Code's web fetch passes pages through a small model, so rules can come back paraphrased. Codex's default sandbox has no network. A clone gives exact text offline.                                                                                                | Tests show one path is enough.                                                                             |
| Hosted on Vercel Hobby at the `vercel.app` domain                                                                                                                                                                               | Free, a preview per PR, and no domain needed to launch. The site URL is set in `astro.config.mjs`, because Vercel's production-URL variable kept the project's first domain after we added an alias.                                                                     | A custom domain, or anything commercial (Hobby is non-commercial).                                         |
| Writing under CC BY 4.0; code and templates under MIT                                                                                                                                                                           | CC licenses aren't meant for code. Templates get copied into projects, so they shouldn't need credit.                                                                                                                                                                    | Never.                                                                                                     |
| Guard the public repo with checks, not care: a gitleaks pre-commit hook, a gitleaks CI job, a private-terms list kept outside the repo, and a validator rule against real email addresses                                       | Agents write most commits, and one pasted key or name is public forever. A check catches what memory misses.                                                                                                                                                             | A false positive blocks real work twice.                                                                   |
| `main` changes only through a squash-merged PR with `check` and `secrets` passing; no approvals required, and no bypass                                                                                                         | Tommy's minimal CI/CD: every change gets the same checks, including his own. A solo maintainer can't approve his own PRs, so approvals would only block him.                                                                                                             | A second maintainer joins.                                                                                 |
| One Markdown file per concern, instead of a JSON registry and script                                                                                                                                                            | Agents read Markdown directly, and people can learn from it. The script added ceremony, not judgment.                                                                                                                                                                    | Agents keep misrouting concerns in evals.                                                                  |
| The site renders the source files as they are, with no copy step                                                                                                                                                                | One source, no drift. Raw `.md` sits at the same path for agents.                                                                                                                                                                                                        | Never, ideally.                                                                                            |
| Astro and Starlight, with a custom landing page                                                                                                                                                                                 | Static, fast, good search. Starlight handles docs pages; the landing page shows personality.                                                                                                                                                                             | Starlight blocks the design we want.                                                                       |
| Core and profile kept apart                                                                                                                                                                                                     | Tommy's preferences shouldn't pose as universal rules.                                                                                                                                                                                                                   | Never.                                                                                                     |
| Voice split by job: voice (every task), writing, learning, tommy                                                                                                                                                                | Every task loads voice, so it stays short. Writing and teaching rules load only when needed. Engineering judgment lives in core and skills, not in voice.                                                                                                                | Agents miss voice rules that only live in writing or learning.                                             |
| ChatGPT drafts voice changes; the repo is the source of truth                                                                                                                                                                   | ChatGPT knows Tommy's voice best. Splitting drafts into the right files keeps each rule in one place.                                                                                                                                                                    | Never.                                                                                                     |
| Learning happens at the PR: a "Worth learning" note in every report, plus a `learn` skill used on demand                                                                                                                        | Tommy's attention lands on PRs when agents run in parallel. Recall practice works best, but quizzes mid-work get switched off. Only `learn` writes LEARNING.md, so parallel agents don't collide.                                                                        | Two weeks of use show he skips walkthroughs, or the notes turn into noise.                                 |
| Agents draft the whole track in Tommy's voice; Tommy reviews and cuts                                                                                                                                                           | Tommy asked for full coverage of the lifecycle first and prioritization after. Reviewing a full draft is faster than writing from outlines.                                                                                                                              | Reviews show the drafts need more rewriting than writing fresh would.                                      |
| The track follows the lifecycle: Understand, Design, Build, Verify, Ship, Operate, Improve                                                                                                                                      | It matches the original content model. Vibe coders rarely see past Build, and the later stages are where production bites. The sidebar groups stops by `stage`.                                                                                                          | Tommy's cut leaves a stage with one stop, so it merges into a neighbor.                                    |
| Each lesson has one home; other stops link to it                                                                                                                                                                                | The audit found the same lesson in up to five stops, and copies were already drifting apart (cliffs said "month" in one place and "30 days" in another).                                                                                                                 | A lesson needs different framing in two stages.                                                            |
| Stops target 800–1,200 words, and "What changes at scale" is dropped unless it's concrete                                                                                                                                       | Tommy's bar is less reading, easier understanding. The template had set the length, not the content.                                                                                                                                                                     | Readers ask for more depth on a stop.                                                                      |
| UI concerns merged into `ui-quality`; the personal-data floor is limited to sensitive data                                                                                                                                      | Every UI change was pulling in five concerns, and every login app was getting GDPR-grade treatment.                                                                                                                                                                      | Evals show agents missing UI issues the merged page doesn't name.                                          |
| The project eval starts a fresh session per scripted turn; `--sessions one` keeps the old single session                                                                                                                        | The second run's one long session made later messages cost 5–10× the early ones, and SWE OS recommends a session per feature, so fresh sessions test what it tells people to do.                                                                                         | Fresh runs lose something real that one session caught, like a decision no file recorded.                  |
| Evals use held-out scenarios, an isolated A arm, and a cost column                                                                                                                                                              | The old scenarios repeated SWE OS text, so B won by recall. The A arm could load globally installed skills.                                                                                                                                                              | Never.                                                                                                     |
| Every guide ends with "How I do it" (Tommy's side-project default, labeled as his), "The standard" (what teams do beyond that, and when you should too), and "Before you ship, check" (3–6 yes/no checks to paste to the agent) | Tommy wanted his habits kept apart from the professional practices he should always look back on. The learner test showed readers skip sections that repeat, so each of the three says something different.                                                              | Readers can't tell the three apart, or skip "The standard".                                                |
| Database lessons show plain SQL first, with short "On Neon" / "On Supabase" lines where steps differ                                                                                                                            | The learner test: the target reader is on Supabase, and Drizzle-first examples made every reader ask "is this for me?" SQL runs in every setup, and it's the fundamental under every ORM.                                                                                | Readers get lost in SQL more than they did in ORM code.                                                    |
| Fonts self-hosted by Astro's `fonts` config, upright Fraunces with `display: optional`                                                                                                                                          | Measured on slow 4G: landing went from 447 KB to 195 KB, load from 2.8 s to 1.3 s, layout shift from 0.19 to 0. No third-party request.                                                                                                                                  | A cold first visit showing the fallback serif bothers us more than layout shift.                           |
| Looping animations: a pause button, paused off-screen, dash animation runs only on arrival                                                                                                                                      | WCAG 2.2.2 needs a pause control. Dash animations repaint on the main thread every frame.                                                                                                                                                                                | We add more motion.                                                                                        |
| Projects keep their docs in the repo: PROJECT.md is the tracker, `docs/design.md` holds the design and a cost table, and `docs/decisions/` gets a file only when a row isn't enough                                             | One builder plus agents doesn't need Jira. Agents read and update files in the same PR as the work. The cost table makes the design something the user agrees to before setup.                                                                                           | A team needs assignments and boards, or the files go stale                                                 |
| A branch and a PR for every change (rule 14), and a ruleset on `main` from setup                                                                                                                                                | Tommy's trunk-based habit lived only in defaults.md, which agents read only when picking a stack                                                                                                                                                                         | A project's own rules say otherwise                                                                        |
| The `learn` walkthrough is one outcome (grade every claim against the code, corrections first, the record last), not five steps                                                                                                 | In the first learn eval, one SWE OS run spent its reply on LEARNING.md and never corrected the user's two wrong answers; every run without SWE OS corrected both. After the change, 2.92 vs 2.53                                                                         | The walkthrough eval stops beating no-SWE-OS on a new model                                                |
